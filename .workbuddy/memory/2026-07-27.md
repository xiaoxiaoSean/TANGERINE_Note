## 第五轮：修复 tip 不显示 + 确认提醒后执行 refreshNotice (workbuddy-20260727)

### Bug 1：tip 不显示
第一次尝试错误地以为是 SunnyUI 问题，加了 this.Activate()。但项目已完全脱离 SunnyUI，UIMessageTip 是自实现的（在 tControl.cs 中）。
真正根因：自实现的 ShowTip 方法在后台线程上调用 Application.Run，但线程未设为 STA（默认 MTA），导致 WinForms 窗口无法正常显示。
修复：tipThread.SetApartmentState(ApartmentState.STA)，并删除 Application.Run 后多余的 tip.Show()。
同时还原 ConfirmReminder 中错误的 this.Activate() 逻辑。

ConfirmReminder 中已有 refreshNotice() 调用，但 twtw.isNoticeEnabled[idx]=false 无边界检查，越界会抛异常导致 refreshNotice 不执行。
修复：添加 idx 边界检查 + refreshNotice 包裹 try-catch。

## 第六轮：修复密码输入框焦点问题 (workbuddy-20260727)

### 问题
程序启动弹出 UIInputForm 密码输入框后，文本框没获得键盘焦点。

### 根因
自实现的 UIInputForm（tControl.cs）构造函数的 Shown 事件中直接调用 Focus()，但 ShowDialog() 在 Shown 事件之后还有默认焦点设置行为，覆盖了 Focus()。BeginInvoke 方案也不行：ShowDialog 的默认焦点行为在消息循环中持续覆盖 BeginInvoke 排队的回调。

### 真正根因
不是文本框焦点问题，而是对话框窗口本身没有获得 Windows 前台焦点。splash 窗口在独立线程运行，持有前台焦点，导致 ShowDialog 显示的对话框无法接收键盘输入。
之前所有方案（Focus/BeginInvoke/ActiveControl/Timer）都在设文本框焦点，但窗口不是前台窗口，文本框自然无法获得键盘输入。

### 修复（最终方案）
用 Win32 API SetForegroundWindow + SwitchToThisWindow 强制将对话框设为前台窗口：
- UIInputForm 添加 SetForegroundWindow/SwitchToThisWindow API 声明
- Shown 事件中：this.Activate() + SetForegroundWindow + SwitchToThisWindow，再用 Timer 延迟设 _editor.Focus()+SelectAll()

0 错误
